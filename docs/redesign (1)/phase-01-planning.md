# Phase 01 — 企画・アイデア（再設計）

> ガイド Phase 01 準拠：ターゲットユーザー特定 → 解決する課題 → 競合調査・差別化 → 収益モデル → MVP 定義。
> 各論点で「v1 現状 → 課題 → 選択肢 → 推奨」を明示する。推奨はユーザー承認をもって確定。

## 1. ターゲットユーザー・ペルソナ

### v1 現状
- 20〜30代、通勤中に1分以内、SNS（𝕏）でバズ狙い、というペルソナ1件のみ（`docs/phases/01-requirements.md` §2）。

### 課題
- ペルソナが1件のみで、利用シーン・モチベーションの幅が浅い。「誰が・なぜ毎日開くか（リテンション動機）」が言語化されていない。

### 再設計案：ペルソナ3層

| 層 | ペルソナ | 像 | 課題(Pain) | PPOI に求めるもの |
|----|----------|----|-----------|------------------|
| メイン | バズ狙いのSNS常用者「ハルト」27歳・会社員 | 通勤電車で𝕏を眺め、面白いネタを探して投稿。反応が快感 | 毎日投稿したいが「ネタ切れ」。考える手間が面倒 | 即シェアできる面白い1ネタ／自分の考察を添えてウケたい |
| サブA | ゆる消費の癒し勢「ミオ」23歳・学生 | 名言・占い・日めくり系アプリが好き。スクショ保存も | 続く習慣アプリが少ない。重い・通知がうるさいと離脱 | 1日1回の軽い楽しみ／きれいなビジュアル／押し付けない通知 |
| サブB | 言葉好きの考察勢「ケンジ」34歳・企画職 | 言葉遊び・大喜利・解釈が好き。コミュニティで語りたい | 一人で考えても発信先がない | 余白のある一句／解釈を投げる場（𝕏）への導線 |

- **共通の核**: 「毎日1回、軽く・面白く・人に見せたくなる」。
- **リテンション動機の言語化**: 「今日だけ」の限定性 + 通知 + シェアによる承認欲求の3点で再訪を作る。

### 決定 ✅
- メイン=ハルト（バズ狙い）。リテンション設計はサブA（習慣）とメイン（シェア）を両立。サブB（考察勢）は𝕏導線で取り込む。（2026-05-31 承認）

## 2. 解決する課題（Pain Point）

### v1 現状
- 「娯楽アプリ」とだけ定義。課題（なぜ必要か）が明示されていない。

### 再設計：このアプリが無いと何に困るか
- **SNSのネタ切れ**: 毎日投稿したい層が「軽くてウケる話題」を探す手間。
- **日々の単調さ**: 通勤・休憩の隙間に「クスッと/ハッと」する小さな刺激がない。
- **解釈・大喜利の発信先不足**: 言葉を解釈して語りたいが、お題と場がない。

### 一言での価値提案
> 「毎日0時、世界で一句だけ。今日しか見られない"っぽい格言"を、あなたの解釈で𝕏へ。」

- 娯楽アプリなので「課題解決」は弱めでよいが、**"今日だけ / 全員同じ / 解釈して共有"** の3点が体験価値の中心。

## 3. 競合調査・差別化

### 競合カテゴリと特徴

| カテゴリ | 例（一般像） | 特徴 | PPOI との違い |
|----------|-------------|------|--------------|
| 名言・格言アプリ | 偉人の名言日替わり表示 | 既存の本物の名言を蓄積・検索・お気に入り | PPOI は **AIが作る"っぽい"創作**。正解がない |
| 日めくりカレンダー | 今日の運勢・一言 | 毎日更新・通知。占い要素 | PPOI は **全員同期 + 当日限定 + 共有が主役** |
| おみくじ・占い | 毎日1回引く | ランダム性・ご利益感 | PPOI は **考察してシェア**する二次創作性 |
| 大喜利・お題アプリ | お題に回答・投票 | コミュニティ内競争 | PPOI は **𝕏 を場として外部化**（アプリ内SNSを持たない軽量さ） |

### 差別化ポイント（再設計で言語化）
1. **「っぽい」=創作格言**という独自ジャンル（本物の引用ではない）。
2. **全ユーザー同期 + 当日限定**による「今日この一句を共有している」一体感とプレミア感。
3. **「考察してシェア」**で正解のない解釈を促し、𝕏 上の大喜利/議論に発展させる設計。
4. **アプリ内SNSを持たない軽量さ**（運営コスト・モデレーション負荷が低い）。

### リスク
- 引用ではないが「本物の格言と紛らわしい」誤認リスク → 共有画像/アプリ内に「っぽい格言（創作）」の明示を検討（Phase 02 機能要件へ）。

## 4. 収益モデルの再検討

### v1 現状
- AdMob のみ。バナー（下部常時）+ インタースティシャル（𝕏共有後）。課金なし（`docs/phases/01-requirements.md` §6）。

### 選択肢比較

| 案 | 内容 | メリット | デメリット | 個人開発適性 |
|----|------|---------|-----------|-------------|
| A. 広告のみ（v1） | バナー + 共有後インタースティシャル | 実装済・無料で導入障壁ゼロ | ARPU 低い。バナーが世界観（プレミア感）を損なう | ◎（現状維持） |
| B. フリーミアム/IAP | 買い切りで「広告除去 + 全テーマ + お気に入り」解放 | 世界観を壊さず収益化。一度の実装 | StoreKit 2 実装コスト。価値が薄いと売れない | ○ |
| C. サブスク | 月額で広告除去 + 限定テーマ等 | 継続収益 | 1日1機能の軽量アプリに月額は割高感・継続率低い | △ |
| D. A+B ハイブリッド | 無料は広告あり、買い切りで広告除去パック | 入口無料 + 課金導線 | 実装・審査項目増 | ○（推奨） |

### 決定 ✅
- **D（A + 買い切り広告除去パック）を採用**。v1 の広告基盤を活かしつつ、プレミア感を求める層に「広告除去 + 全テーマ + お気に入り/コレクション」を一括買い切りで提供。サブスクより軽量アプリの体験に合う。（2026-05-31 承認）
- 価格: **¥400 の買い切り**（初期値、リリース後に市場検証して見直し可）。
- 導入時期: v2.0（W5〜W8）。v1.1/v1.2 は広告のみで先行。

## 5. MVP の再定義（Must / Should / Won't）

### v1 現状スコープ
- Must: 今日の格言表示 / 当日のみ / 考察シェア / テーマ3択 / 通知。
- Should: お気に入り、字体A/B。Won't: 過去閲覧、ユーザー生成、SNS機能、課金。

### 再評価の論点

| 論点 | v1 | 課題 | 再設計案 |
|------|----|------|---------|
| 過去閲覧 | Won't（当日のみ） | プレミア感の核だが、再訪後の"見るものがない"離脱リスク | 当日限定は**維持**。ただし「自分が共有/お気に入りした分だけ」振り返れる導線を検討 |
| お気に入り | Should | 振り返り需要・課金価値の源泉 | **Must 寄りに格上げ**（保存はローカルのみ＝当日限定の世界観を壊さない範囲で） |
| ストリーク（連続記録） | なし | 習慣化（リテンション）動機が弱い | **Should 新規**：連続閲覧日数の表示で再訪動機を付与 |
| ウィジェット | なし | ホーム画面での想起・流入 | **Should 新規**：今日の格言ウィジェット |
| 課金 | Won't | 収益機会 | §4 の推奨次第で **Should（買い切り）** |
| 創作明示 | 暗黙 | 本物誤認リスク | **Must 新規**：共有画像/UI に「創作」明示 |

### 再設計 MVP（v1.1 候補）

**Must**
- 今日の格言を1件表示（日付ベース・全員同期・当日のみ）
- 「考察してシェアする」（画像共有メイン + 短い考察テキスト）
- テーマ選択（和風 / ポップ / ダーク）
- ローカル通知（デフォルト時刻、設定で変更可）
- 「っぽい格言（創作）」の明示

**Should**
- お気に入り保存（ローカル、当日分の振り返り）
- ストリーク表示
- 今日の格言ウィジェット
- 字体 A/B（serif / default）
- 買い切り（広告除去 + 全テーマ等）※ §4 承認時

**Won't（今回も見送り）**
- 過去全アーカイブの自由閲覧
- ユーザーによる格言生成
- アプリ内コメント・いいね等の独自SNS
- Android / Web / 管理画面 / ログイン

### 決定 ✅
- Must は v1 踏襲 + 「創作明示」追加。Should の優先度を確定（2026-05-31 承認）:
  - **v1.1**: お気に入り保存 / ストリーク表示（+ Must の創作明示）
  - **v1.2**: 今日の格言ウィジェット
  - **v2.0**: 買い切り（広告除去 + 全機能）
  - 字体 A/B は継続検証（v1.1 に含めるが計測のみ）
- Won't は変更なし。
