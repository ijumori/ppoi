## 2. 残課題（提出前に必ず潰すもの）

### 2.1 ✅ Critical — PaywallView 謳い文句 vs 実装の乖離（**対応済み 2026-06-22**）

**問題:** PaywallView は「お気に入り無制限」と謳うが、`FavoritesStore` は無料/有料を区別せず一律 100 件上限だった。再却下リスク高。

**採用設計:** `toggleFavorite(_:isPremium:)` で呼び出し側から `isPremium` を渡す方式。

設計検討の経緯:
- 当初 `@MainActor` 化 + closure 注入で実装 → `AppState` の非 MainActor 初期化と衝突
- 設計を再検討（ユーザー指示「実行前に十分に検討して」）
- 結論: 引数渡しが明示的・並行安全・テスト容易（closure default が actor-isolated 状態に触れる問題を回避）

実装内容（`FavoritesStore.swift`）:

```swift
static let freeLimit = 10
static let premiumLimit = 1000  // 実質無制限・UserDefaults JSON 肥大防止

enum ToggleResult: Equatable {
    case added
    case removed
    case limitReached(limit: Int, isPremium: Bool)
}

@discardableResult
func toggleFavorite(_ quote: Quote, isPremium: Bool) -> ToggleResult {
    if let index = list.firstIndex(where: { $0.id == quote.id }) {
        list.remove(at: index); persist(); return .removed
    }
    let limit = isPremium ? Self.premiumLimit : Self.freeLimit
    if list.count >= limit {
        return .limitReached(limit: limit, isPremium: isPremium)
    }
    list.insert(quote, at: 0); persist(); return .added
}
```

UI 側（`QuoteView` / `QuoteDetailView`）:
- `@Environment(StoreManager.self) private var storeManager` を追加
- `toggleFavorite(quote, isPremium: storeManager.isPurchased)` を呼び出し
- `.limitReached(_, isPremium: false)` のときに `showFavoritesPaywall = true` で PaywallView をモーダル表示

テスト（`PPOITests/UserDefaultsStoreTests.swift`）:
- `test_freeUser_blockedAt10` — 10件まで追加可、11件目で `.limitReached(limit: 10, isPremium: false)`
- `test_premiumUser_canExceed10` — プレミアムは50件追加可
- `test_toggleFavorite_addsThenRemoves` — 既存挙動の互換確認
